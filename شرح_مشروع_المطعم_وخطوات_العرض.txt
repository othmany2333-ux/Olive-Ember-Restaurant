OLIVE & EMBER | دليل المشروع والعرض أمام الدكتور
============================================================
اسم المشروع: Restaurant Management & Online Food Ordering System
نوع المشروع: تطبيق واجهات أمامية (Front-End Educational Demo)
التقنيات: React.js - JavaScript (JSX) - React Router - Material UI - Vite
اللغة المستخدمة في الواجهة: الإنجليزية

01 | فكرة المشروع
----------------
Olive & Ember هو موقع تجريبي لمطعم يعرض قائمة الطعام، ويسمح للزبون بإنشاء حساب
وتصفح الوجبات والبحث عنها وتصفيتها وترتيبها، وإضافتها إلى السلة، وإرسال طلب
تجريبي ومتابعة حالته. ويتيح حساب المدير إدارة الأطباق والتصنيفات والطلبات
والمستخدمين ورسائل الزبائن والتقييمات، مع لوحة تقارير تعرض ملخصات مرئية.

المشروع تعليمي، ويستهدف توضيح المهارات التي تمت دراستها في React. لا توجد فيه
بوابة دفع إلكتروني أو خادم أو قاعدة بيانات مشتركة؛ يتم حفظ المعلومات في
localStorage داخل المتصفح نفسه. لذلك لا تنتقل البيانات تلقائياً بين الأجهزة.

02 | الهدف من المشروع
---------------------
- بناء تطبيق متعدد الصفحات باستخدام React ومكونات قابلة لإعادة الاستخدام.
- تطبيق إدارة الحالة باستخدام useState وuseEffect وuseContext وCustom Hook.
- فصل صلاحيات الزبون (User) عن صلاحيات المدير (Admin) داخل الواجهة.
- تنفيذ CRUD على الوجبات مع نماذج الإدخال والتحقق من البيانات.
- استخدام MUI والمظهر الموحد Theme والنوافذ Dialog والقائمة الجانبية Drawer.
- توفير بحث وتصفية وترتيب وتصميم يستجيب لأحجام الشاشات المختلفة.
- توضيح الترابط بين الواجهات والمنطق البرمجي بملفات منظمة.

03 | الصفحات ومساراتها
----------------------
/                 الصفحة الترحيبية العامة قبل تسجيل الدخول: Landing/Home
/about            التعريف بالمطعم
/menu             عرض قائمة الطعام والبحث والتصفية والترتيب
/contact          نموذج إرسال رسالة لإدارة المطعم
/login            تسجيل الدخول
/register         إنشاء حساب جديد
/cart             سلة المشتريات وإتمام طلب تجريبي
/discover         الصفحة المخصصة للمستخدم بعد تسجيل الدخول
/account          لوحة المستخدم: الطلبات وتعديل الاسم والبريد
/messages         رسائل وتقييمات المستخدم
/admin            لوحة المدير: الأطباق والطلبات والرسائل والمستخدمون والتقارير
أي مسار غير معروف  صفحة 404

ملاحظة: الصفحات /discover و/account و/messages محمية لدور User، وصفحة /admin
محمية لدور Admin؛ ويتم التوجيه بحسب نوع الحساب بعد تسجيل الدخول.

04 | أنواع المستخدمين
----------------------
أ- الزائر: مشاهدة الصفحة الرئيسية والمعلومات وقائمة الطعام والتواصل، ويمكنه
   وضع وجبات في السلة؛ إتمام الطلب يتطلب تسجيل الدخول.
ب- الزبون (User): إنشاء حساب أو تسجيل دخول، استعراض وطلب الوجبات، الاطلاع على
   الطلبات الخاصة به، تعديل الاسم والبريد، إرسال رسالة أو تقييم.
ج- المدير (Admin): إدارة الوجبات CRUD، التصنيفات، حالات الطلبات، مراجعة
   الرسائل والتقييمات، تغيير صلاحيات حسابات أخرى، ومشاهدة التقارير.

الحسابات التجريبية (لا تستخدمها لبيانات حقيقية):
Admin   البريد: admin@oliveember.test  | كلمة المرور: Admin123!
User    البريد: guest@oliveember.test | كلمة المرور: Guest123!

05 | الوظائف الأساسية وشرحها
----------------------------
1. قائمة الطعام: تُعرض الأطباق من حالة مشتركة في RestaurantContext.
2. البحث والتصفية والترتيب: تعمل الدالة filterAndSortMenu على نسخ القائمة
   وتصفيتها بحسب النص والتصنيف، ثم ترتيبها بحسب الاسم أو السعر أو التميّز.
3. السلة: عند الضغط على Add to Cart يتم استدعاء addToCart وتحديث الكمية.
4. إتمام الطلب: يُجمع محتوى السلة، ويُنشأ سجل طلب بعد التحقق من تسجيل الدخول
   وبيانات الاستلام، ثم تُفرَّغ السلة.
5. CRUD: يستطيع المدير إضافة طبق جديد، عرض الأطباق، تعديلها أو حذفها.
6. حالات الطلب: Received / Preparing / On the way / Delivered / Cancelled.
7. الرسائل والتقييمات: يُرسل الزبون مراجعة؛ لا تظهر للعامة إلا بعد موافقة
   المدير. الرسائل الخاصة لا تُنشر في الصفحة الرئيسية.
8. الصلاحيات: ProtectedRoute يتحقق من حالة الدخول والدور قبل فتح صفحة محمية.
9. الملف الشخصي: يمكن للمستخدم تعديل الاسم والبريد الإلكتروني مع التحقق من
   صحة الإدخال ومنع تكرار البريد.
10. الإدارة والتقارير: تشمل عدد الطلبات والأطباق، متوسط قيمة الطلبات التجريبية
    وتوزيع الأطباق على التصنيفات وحالات الطلب بواسطة أشرطة مقارنة MUI.

07 | كيف تعمل تقنيات React في هذا المشروع؟
------------------------------------------
React Components: تفصل كل صفحة أو عنصر واجهة إلى مكوّن مستقل يسهل تعديله.
Props: تُمرر بيانات الوجبة مثلاً من صفحة القائمة إلى مكوّن DishCard.
useState: تحفظ حالات مؤقتة مثل نص البحث والنوافذ المفتوحة وحقول النماذج.
useEffect: تستخدم لمزامنة القيم إلى localStorage ومراجعة التصنيف المختار.
useContext: تجعل الحساب والسلة والطلبات متاحة لمكونات مختلفة من دون Props متتالية.
Custom Hooks: useLocalStorage يجمع منطق قراءة/حفظ البيانات في مكان واحد.
useMemo: يُستخدم لحساب نتائج مشتقة مثل عناصر السلة والقائمة المصفاة.
React Router: يربط المسار بالمكوّن المناسب دون إعادة تحميل صفحة الويب.
useNavigate: يُستخدم بعد تسجيل الدخول أو إتمام الطلب للانتقال برمجياً.
MUI Theme: يوحّد المظهر؛ Dialog للنماذج والتأكيد؛ Drawer للقائمة الجانبية.

08 | تشغيل المشروع في VS Code (Windows / macOS / Linux)
------------------------------------------------------
1) فك ضغط ملف مشروع الفاينل، ثم افتح مجلد olive-ember نفسه في VS Code.
2) تأكد من تثبيت Node.js (إصدار 20 أو أحدث) وnpm.
3) افتح Terminal > New Terminal.
4) نفّذ الأوامر التالية بالترتيب:

   node -v
   npm -v
   npm install
   npm run dev

5) افتح العنوان الذي يعرضه Vite؛ غالباً http://localhost:5173/
6) لإيقاف الخادم اضغط Ctrl + C داخل Terminal.

أوامر الفحص قبل التسليم:
   npm test          اختبارات وظائف JavaScript.
   npm run build     التأكد من إمكانية إنشاء نسخة الإنتاج.
   npm run preview   معاينة نسخة الإنتاج بعد البناء.

يُفضل تشغيل هذه الأوامر على نفس الكمبيوتر الذي ستعرض عليه الموقع.

09 | خطة عرض حقيقية أمام الدكتور (حوالي 5 إلى 7 دقائق)
----------------------------------------------------
الدقيقة 1: قدم الفكرة بإيجاز واشرح الفرق بين الزائر والزبون والمدير.
الدقيقة 2: اعرض / ثم /menu ونفّذ بحثاً وترتيباً حسب السعر وتصفية بتصنيف.
الدقيقة 3: سجل دخول الزبون؛ أضف وجبتين وغيّر الكمية وأكمل طلباً تجريبياً.
الدقيقة 4: افتح /account لعرض الطلب وتعديل ملف المستخدم، ثم /messages
           لإنشاء تقييم جديد.
الدقيقة 5: سجل الخروج وادخل بحساب المدير؛ افتح /admin وشاهد الطلب.
الدقيقة 6: غيّر حالة الطلب ونفّذ إضافة طبق وتعديل السعر ثم الحذف، ثم وافق
           على التقييم ليظهر على الصفحة العامة.
الدقيقة 7: افتح src/App.jsx وAuthContext.jsx وRestaurantContext.jsx واشرح
           التنقل وإدارة البيانات وProtectedRoute، ثم اعرض نافذة جوال.

10 | تقديم شفهي قصير بصياغة طبيعية (يمكنك تعديله بأسلوبك)
---------------------------------------------------------
السلام عليكم دكتور. اسم المشروع Olive & Ember، وهو نظام تجريبي لإدارة مطعم
وطلب الطعام عبر الويب. ركزت فيه على تطبيق مفاهيم React التي تعلمناها، وليس
مجرد تصميم صفحات ثابتة. الزبون يستطيع مشاهدة الأطباق والبحث عنها وتجهيز
سلة وإرسال طلب، بينما المدير يراجع الطلبات ويدير الوجبات والتقييمات. قسمت
المشروع إلى صفحات ومكونات واضحة، واستخدمت React Router للتنقل وContext
لمشاركة بيانات المستخدم والمطعم، واستفدت من Material UI لتنظيم التصميم.
البيانات الآن محفوظة محلياً في المتصفح لأن هذا مشروع Front-End تعليمي، وأعرف
أن تحويله لنظام حقيقي يحتاج إلى خادم وقاعدة بيانات وحماية للحسابات.

اختر تعبيراتك الخاصة أثناء العرض؛ الأهم أن تشرح ما تستطيع تنفيذه وفهمه فعلاً.

11 | كيف يتم التسليم للدكتور؟
-----------------------------
- تأكد أولاً من موافقة الدكتور على فكرة المشروع بحسب تعليمات المادة.
- شغّل المشروع واختبر الحسابين وعمليات CRUD والطلبات والرسائل على جهازك.
- نفّذ npm test وnpm run build، ولا تعتمد على نجاح اختبارات المنطق وحدها.
- ارفع ملفات المصدر والأصول إلى GitHub (لا ترفع مجلد node_modules).
- أرسل رابط Repository عبر البريد الإلكتروني كما ورد في تعليمات الدكتور.
- اكتب اسم الطالب ورقمه الجامعي وبيانات المادة الصحيحة في التقرير قبل تقديمه.
- راجع أي قواعد خاصة بالأصالة الأكاديمية، وقدّم وصفاً صادقاً لطريقة إنجاز العمل.

12 | حدود النسخة الحالية ونقاط يجب معرفتها
-------------------------------------------
- localStorage ليس قاعدة بيانات مشتركة؛ لكل متصفح نسخته من بيانات المشروع.
- كلمات المرور التجريبية محفوظة في المتصفح وغير آمنة للاستخدام الحقيقي.
- حماية ProtectedRoute من واجهة المستخدم تعليمية؛ الحماية الحقيقية تحتاج Backend.
- لا يوجد نظام دفع فعلي أو رسائل بريد إلكتروني فعلية أو نظام توصيل متصل بخادم.
- تقارير الإيرادات مبنية على طلبات تجريبية وليست مبيعات حقيقية.
- نجحت 14 من 14 اختبارات منطق محلية أثناء إعداد الحزمة؛ لم يتم التحقق من
  npm run build أو تشغيل الواجهة في المتصفح بهذه البيئة بسبب تعذر تنزيل npm.
  قبل التسليم، عليك تنفيذ npm install ثم npm run build وتجربة جميع المسارات.
